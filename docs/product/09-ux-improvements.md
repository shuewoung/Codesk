## 设计约定

- “当前设备”指正在使用客户端的手机或电脑；“宿主机”指运行 Hub 的电脑。
- 宿主机引用使用文件路径上下文；当前设备文件先上传到 Hub。来源必须保留在草稿和显示卡片中。
- “本次产物”需要轮次/工具成功与存在证据；最近修改的项目文档仅作为候选文档，不自动认定为本轮交付。
- 下载原件与预览独立。Office 的 PDF/HTML sidecar 是预览版本；原件下载必须保持原始字节。
- 传输契约见 [04-protocol.md](04-protocol.md)。新增 requestId/taskId、分块下载、文件能力和退出语义均以该文档和实际实现为准。
- 无服务端确认的退出只可称“仅本地退出”。共享配对码与设备凭据不是同一对象。

## 功能边界与兼容性

1. **产物不是全量自动识别。** 当前识别成功结构化输出中的 `outputPath/output_path/savedPath/outputPaths`、明确成功退出配合 Saved/Created/Written/Output 等输出路径，以及通过 call_id 确认是 apply_patch 后的标准成功 A/M 路径（D 删除项排除）。只索引 rollout 尾部 4 MiB，`coverage` 显示范围是否截断；无轮次边界时明确标为会话已确认文件。不会仅凭修改时间认定生成归属，任意脚本未输出可识别证据时可能遗漏产物。
2. **结果回看是基础版。** 当前展示最后可见助手答复的有界摘录与状态，不调用模型重新总结，不自动汇总所有验证结果或产物链接，不宣称测试通过。
3. **诊断是基础版。** 展示连接模式/状态、已有握手反馈、脱敏端点和待响应请求数；没有 RTT、吞吐测量或完整链路主动探测。
4. **上传恢复有进程边界。** 重试负载仅在内存，应用重启后未完成上传需重选；读取失败需移除重选。上传成功而草稿保存失败时可重试保存，不重复上传。LAN 大文件结果使用原任务闭包归属，WS 使用任务和请求 ID。
5. **文件访问比旧版严格。** 带会话 ID 的操作仅允许该会话已有目录和上传目录；旧无会话 ID 请求只允许服务端已知会话根。请求传入的 cwd 不能授权新目录，私有 Hub/Codex 数据不可读取，旧 basename 猜测回退不再支持。
6. **下载是有限资源能力。** 原件上限 20 MiB、256 KiB 分块，校验序号/长度/SHA-256；每连接最多两项、全局最多四项，带超时和取消。HTTP 快照采用有界同步读取，大文件可能短暂占用 Hub 事件循环；中继缓冲采用并发限制与节流，并非无限带宽。
7. **安装下载优先保证版本。** 当前没有可信的同版本官网镜像约定，因此只在解析目标发布后下载固定 tag，不臆造镜像或静默使用旧版本。网络失败保留原安装。
8. **不等于已发布。** 本轮没有提交、推送、重启正在使用的 Hub、打包/安装新 APK 或发布安装器。现有运行实例和旧 APK不会自动获得源码改动。
